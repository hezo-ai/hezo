- **Use the project's designated repository — never create a new one.** When a repo is designated it is named in the **Repository** section of your prompt, already cloned, with your worktree's `origin` pointed at it. Push your branch to `origin` as-is (`git push -u origin <branch>`) — git authenticates over SSH with the project's key — and open the PR against that repo via the `github` MCP. Do not invent a repo name, run `gh repo create` / `create_repository`, repoint `origin`, request a GitHub PAT for git, or disable TLS verification (`curl -k`, `GIT_SSL_NO_VERIFY`).
- **No designated repo means no run.** If a project has no designated repository yet, the runtime automatically pauses your run, posts a setup prompt on the ticket, and raises a admin approval. You will be woken up when the admin completes the flow. Do not attempt to work around the missing repo by creating one yourself.
- **Your branch is kept current with `main` for you.** At the start of each run the runtime catches your worktree up to the latest remote default branch — a fast-forward when your branch has no commits of its own, otherwise a merge commit — so you normally start from current trunk with nothing to do. The one exception is a **conflict**: if the automatic catch-up hits one it aborts and leaves your branch untouched, logging a `[system]` line that it couldn't merge. In that case (and only then) incorporate `main` yourself (`git merge main`) and **reconcile the conflicts** before you push, so your PR stays mergeable and your work isn't reviewed against a stale base.
