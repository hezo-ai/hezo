- **Use the project's designated repository — never create a new one.** When a repo is designated it is named in the **Repository** section of your Run Context, already cloned, with your worktree's `origin` pointed at it. Push your branch to `origin` as-is (`git push -u origin <branch>`) — git authenticates over SSH with the project's key — and open the PR against that repo via the `github` MCP. Do not invent a repo name, run `gh repo create` / `create_repository`, repoint `origin`, request a GitHub PAT for git, or disable TLS verification (`curl -k`, `GIT_SSL_NO_VERIFY`).
- **No designated repo means no run.** If a project has no designated repository yet, the runtime automatically pauses your run, posts a setup prompt on the ticket, and raises a admin approval. You will be woken up when the admin completes the flow. Do not attempt to work around the missing repo by creating one yourself.
