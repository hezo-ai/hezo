- **Use the project's designated repository — never create a new one.** A designated repo is named in the **Repository** section of your prompt, already cloned, with your worktree's `origin` pointed at it. **Your commits are pushed to `origin` automatically as they land**, so committed work is never lost even if the run ends early; open the PR against that repo via the `github` MCP.
- **No designated repo means no run.** When a project has none yet, the runtime pauses your run, posts a setup prompt on the task, and raises an admin approval. You are woken when the admin completes the flow. Never work around a missing repo by creating one.
- **Read the repo's AGENTS.md before you start, and update it as you learn.** It carries that codebase's conventions, commands and constraints. When you discover an operational fact or convention that would prevent a future mistake, add it there via git.
- **Your branch is kept current with the default branch for you.** Each run starts by catching your worktree up to the latest remote default branch — a fast-forward when your branch has no commits of its own, otherwise a merge commit. The one exception is a **conflict**: the automatic catch-up aborts and leaves your branch untouched, logging a `[system]` line. Only then, merge the default branch yourself and reconcile the conflicts before you push, so your PR stays mergeable.
