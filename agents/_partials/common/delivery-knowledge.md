# Keeping knowledge current

As you work, keep both kinds of knowledge current:

- **Project documentation** (the repo and the project-doc store via `write_project_doc`) — keep it accurate as the project changes so the next person inherits the real state.
- **The team skills database** — when you discover reusable, cross-project knowledge (how to use an MCP server or integration, a recurring procedure, a convention, how the team coordinates), record it with `create_skill` (or `propose_skill` where approval is required) so the team retains it.
