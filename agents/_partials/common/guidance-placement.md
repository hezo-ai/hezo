## Where new guidance belongs

When you capture a reusable lesson, convention, standard, or fact, put it at the level where it does the most good — decide by **who needs it** and **when they need it**:

- **All of this project's agents, always** → the project **Custom Prompt** via `update_project_custom_prompt`. It is injected verbatim into every agent's system prompt in this project on every run, so it's the right home for a shared convention, standard, or fact the whole team must carry from the start of each run. Read the current value first with `get_project_custom_prompt` and extend it — the content you pass replaces the whole thing. This saves editing each agent's prompt one by one.
- **One role, always** → that agent's own system prompt via `update_agent_system_prompt` (add it under `## Learned Rules`). Use this only for guidance that a single role needs.
- **A reusable how-to, pulled in when relevant** → a **skill** via `create_skill` (choose its reach — `scope: global` to share with every project, `scope: project` to keep it here; a skill can be project-scoped, so scope is *not* what separates a skill from a doc). Skills are pulled in when relevant rather than always present — right for a procedure, integration playbook, reference, or **a reusable technique or working method you figured out for a recurring kind of task** (the tool that actually works, the sequence of steps that succeeds), loaded only when the situation calls for it. Prefer a skill for a reusable how-to even when a per-role `## Learned Rules` line would also work: a learned rule reaches one role in one team, whereas a skill is loaded on demand by any agent — and `scope: global` reaches every team — so the same discovery isn't re-derived elsewhere.
- **This project's state or spec, read on demand** → a **project doc** via `write_project_doc` — requirements, designs, plans, research (content an agent *reads to know the project*, not a procedure it executes). A short manifest is always in context; the full content is pulled on demand.

Rule of thumb: must it be present from the very start of the run → the project Custom Prompt (all agents) or an agent's system prompt (one role); can it be pulled when relevant → a skill or a project doc — and between those two, decide by *kind*, not reach: a reusable how-to an agent **executes** is a skill (at `global` or `project` scope, so a procedure specific to this project is still a project-scoped skill), whereas this project's state or spec an agent **reads** is a project doc. Reach for the narrowest scope that still covers everyone who needs it.
